the one rule

Proven findings, or it's not a finding

The LLM may propose a bug, but it never gets to declare one real. A finding only counts if the engine can replay an exact request and re-confirm it. Everything it can't reproduce is demoted to a dimmed "suspected" lane that never touches your grade.

  • Re-run it after you patch — a bug is only "fixed" when its saved exploit is replayed and no longer reproduces, never just because this scan didn't trip it.
  • Secrets never hit disk — credential-bearing proofs are never written to the run history.
  • Safe by default — fails closed to localhost / private ranges; a public host needs an ownership token served at a well-known path before a single aggressive request.
  • Budgeted — minutes and dollars, with a live spend meter, not an open-ended crawl.
the wedge

The bugs a signature scanner can't see

ZAP and Nuclei match patterns. They can't reason about your auth flow. Vibe Check is app-aware, so it finds the business-logic holes that actually get vibe-coded apps owned.

IDOR / BOLA critical

Fetches the same object as two logged-in users. Identical private data back = the endpoint never checks ownership. Anyone can read anyone's records.

Mass assignment critical

Signs up sending "role":"admin". If the server honors a client-supplied field, a new user just made themselves staff.

Guessable reset tokens critical

Catches a password-reset flow that hands the token back in its response — or issues one short enough to guess. Either one is account takeover.

Plus the hygiene a launch skips: exposed .env / dumps / client secrets, CORS that reflects any origin, open redirects, stack-trace leaks, GraphQL introspection, reflected input, host-header injection, missing security headers, insecure cookies — each one proven, not guessed.
